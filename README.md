# cloud-init-to-butane

`c2b` is a Go-based transpiler that converts [Cloud-Init](https://cloudinit.readthedocs.io/) `cloud-config` YAML into [Butane](https://www.flatcar.org/docs/latest/provisioning/config-transpiler/) configuration for Flatcar Container Linux.

The project is focused on the configuration used when provisioning Flatcar worker nodes with Cluster API.

The current repository is an early prototype. The planned mentorship work will expand and harden the translator based on the configuration actually generated by Cluster API's Kubeadm Bootstrap Provider (CABPK).

## Current Features

The prototype currently supports the following parts of `cloud-config`:

### Users and Groups

Maps:

```yaml
users:
  - name: flatcar-admin
    ssh-authorized-keys:
      - "ssh-rsa ..."
    groups: "sudo, docker"
```

to the corresponding Butane `passwd.users` and `passwd.groups` configuration.

Currently supported user information includes:

- username
- SSH authorized keys
- group membership

Other Cloud-Init user options are currently parsed but may not be translated.

### `write_files`

Maps Cloud-Init `write_files` entries to Butane `storage.files`.

Currently supported:

- file path
- file contents
- permissions
- owner username
- `append`
- `b64` / `base64` encoding

Permissions are converted from the usual Cloud-Init string representation to the integer value expected by Butane. For example:

```text
"0644" → 420
```

For an owner such as:

```text
root:root
```

the current implementation maps the username but does not yet map the group.

### `runcmd`

The parser supports both string commands and list-form commands, for example:

```yaml
runcmd:
  - "systemctl start kubelet"
  - [systemctl, restart, ssh]
```

List-form entries are shell-quoted so that arguments with spaces or special characters are preserved. All commands are collected into a single script file (run with `set -e`, so a failure stops execution) and executed once during first boot by a oneshot systemd unit, made idempotent with a marker file.

## Example

### Input

```yaml
#cloud-config

users:
  - name: flatcar-admin
    ssh-authorized-keys:
      - "ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABgQC..."
    groups: "sudo, docker"
    sudo: "ALL=(ALL) NOPASSWD:ALL"

write_files:
  - path: /etc/kubernetes/kubelet.conf
    permissions: "0644"
    owner: "root:root"
    content: |
      server: https://127.0.0.1:6443
      token: abcdef.0123456789abcdef

runcmd:
  - "echo 'Bootstrapping ClusterAPI Node...' > /var/log/bootstrap.log"
  - "systemctl enable kubelet.service"
  - "systemctl start kubelet.service"
```

### Current output

```yaml
variant: flatcar
version: 1.1.0
passwd:
    users:
        - name: flatcar-admin
          ssh_authorized_keys:
            - ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABgQC...
          groups:
            - sudo
            - docker
storage:
    files:
        - path: /etc/kubernetes/kubelet.conf
          mode: 420
          user:
            name: root
          contents:
            inline: |
                server: https://127.0.0.1:6443
                token: abcdef.0123456789abcdef
        - path: /opt/c2b/runcmd.sh
          mode: 448
          contents:
            inline: |-
                #!/bin/sh
                set -e
                echo 'Bootstrapping ClusterAPI Node...' > /var/log/bootstrap.log
                systemctl enable kubelet.service
                systemctl start kubelet.service
systemd:
    units:
        - name: c2b-runcmd.service
          enabled: true
          contents: |-
            [Unit]
            Description=Execute cloud-init runcmd
            Wants=network-online.target
            After=network-online.target
            ConditionPathExists=!/var/lib/c2b-runcmd.success

            [Service]
            Type=oneshot
            ExecStart=/opt/c2b/runcmd.sh
            ExecStartPost=/bin/touch /var/lib/c2b-runcmd.success

            [Install]
            WantedBy=multi-user.target
```

The generated configuration can be passed through the official Butane CLI to check whether it is valid:

```sh
./c2b -i test/test.YAML | butane --pretty
```

## Installation and Build

The project currently requires Go 1.22 or newer.

Build the CLI with:

```sh
go build -o c2b ./cmd/c2b
```

The `Makefile` is currently only a stub, so `go build` should be used for now.

## Usage

Read a Cloud-Init YAML file and print the generated Butane configuration:

```sh
./c2b -i test/test.YAML
```

Write the generated configuration to a file:

```sh
./c2b -i test/test.YAML -o output.bu
```

Validate the generated configuration with Butane:

```sh
./c2b -i test/test.YAML | butane --pretty
```

### CLI Options

| Flag | Description |
| --- | --- |
| `-i` | Input `cloud-config` YAML file. Required. |
| `-o` | Output Butane file. If omitted, output is written to stdout. |

## Project Structure

```text
cmd/c2b/
└── main.go                    CLI entry point

internal/cloudinit/
├── parser.go                  YAML parsing and custom type handling
└── types.go                   Cloud-Init data types

internal/transpiler/
├── engine.go                  Runs the registered translators
├── interface.go               Translator interface
└── translators/
    ├── users.go               Users/groups to passwd
    ├── files.go               write_files to storage.files
    └── runcmd.go              runcmd to systemd unit

internal/butane/
├── types.go                   Butane output types
└── generator.go               Butane YAML generation

test/
└── test.YAML                  Sample Cloud-Init configuration
```

## How It Works

The translation process is split into three main parts:

```text
Cloud-Init YAML
      │
      ▼
Cloud-Init parser
      │
      ▼
Transpiler
      │
      ├── users/groups
      ├── write_files
      └── runcmd
      │
      ▼
Butane configuration
      │
      ▼
Ignition JSON
```

The parser converts the input YAML into typed Go structures. The transpiler then runs the individual translators and builds the Butane configuration. Finally, the generator writes the resulting configuration as Butane YAML.

The generated configuration currently uses:

```yaml
variant: flatcar
version: 1.1.0
```

## Current Limitations

This repository is still an early prototype. Some parts of the translation are incomplete or need further work.

### Users

Some Cloud-Init user fields are currently parsed but not translated, including:

- `sudo`
- `hashed_passwd`
- `lock_passwd`
- `uid`
- `gid`
